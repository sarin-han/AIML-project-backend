# 채팅·음성 편집 설계

상태: 구현 전 설계 단계입니다. 앞부분(요약)만 읽어도 전체 그림을 알 수 있고, 뒷부분(상세)에 구현 내용이 있습니다.


# 요약

## 한 줄 설명

채팅창에 쓰거나 마이크로 말하면, AI가 알아듣고 편집 화면을 대신 조작해 줍니다.

## 예시

- "클립 1 길이 1초만 더 늘려줘"
- "클립 2랑 클립 3 위치 바꿔줘"
- "클립 2에 '진짜 맛있겠다' 자막 달아줘"

## 어떻게 동작하나

말하기(또는 입력) → 글자로 변환(음성일 때만, Whisper) → AI(OpenAI)가 문장을 "편집 명령"으로 변환 → 프로그램이 명령을 검사하고 편집 화면에 적용 → 결과 안내와 되돌리기

- AI는 "무엇을 바꿀지"만 정합니다. 예를 들어 "클립 1의 끝 시간을 1초 늘린다"라는 명령을 만들어 줍니다.
- 실제 수정은 우리 프로그램이 합니다. 마우스로 편집할 때와 같은 기능을 호출하므로, 잘못 알아들어도 검사에서 걸러지고 ⌘Z로 되돌릴 수 있습니다.
- 영상 파일은 건드리지 않습니다. 구간과 자막 같은 편집 정보만 바뀌고, "내보내기"를 누를 때 영상이 만들어집니다.

## 음성 입력

마이크 버튼을 누르고 말하면 녹음해서 서버의 Whisper로 보내 글자로 바꿉니다. 브라우저 내장 인식 대신 서버 방식을 써서 Safari에서도 되게 할 계획입니다.

## 쓰기 편하게 하는 장치

- 애매하면 "클립 2가 두 개인데 어느 쪽인가요?"라고 되묻습니다.
- 삭제 같은 큰 변경은 실행 전에 한 번 확인합니다.
- 한 번에 말한 여러 명령은 되돌리기 한 번으로 모두 취소됩니다.

## 구현 순서

1. 글로 편집 (클립 길이·순서, 자막 추가·이동·스타일)
2. 음성 입력 연결
3. 되묻기·확인 화면 다듬기


# 상세

## 1. 전체 구조

흐름은 다음과 같습니다.

마이크 녹음 또는 텍스트 입력 → (음성인 경우) 백엔드 /stt → GPU 서버의 faster-whisper large-v3 → 백엔드 /agent/chat에 문장과 편집 상태 전달 → OpenAI tool calling(gpt-4o-mini, 환경변수로 교체 가능) → 응답으로 안내 문구(reply)와 명령 목록(actions) 반환 → 프론트가 검증 후 실행(되돌리기 1번 단위) → 결과 표시

각 위치의 역할은 다음과 같습니다.

- 프론트(React + TypeScript): 편집 상태는 EditorScreen.tsx에 있습니다(구간, 자막, 스타일, 스냅샷 기반 되돌리기/다시 실행). 입력 UI, 명령 실행기(dispatcher), 검증을 담당합니다.
- 백엔드(FastAPI, 로컬): /agent/chat, /stt 중계를 추가합니다. OpenAI 키는 로컬 백엔드에만 둡니다.
- GPU 서버(FastAPI): /stt(짧은 오디오를 텍스트로)를 추가합니다. Whisper는 이미 필요할 때 로드되어 상주합니다.

## 2. 요청에 담는 편집 상태

영상이나 프레임은 보내지 않고 텍스트만 보냅니다. 담는 항목은 다음과 같습니다.

- 영상 길이, 현재 재생 위치, 선택된 구간
- 구간 목록: id, 이름(클립1, 클립2…), 시작, 끝, 배속, 음소거 여부
- 자막 목록: id, 시작, 끝, 문구
- 가장 최근에 만지거나 만든 대상(자막 또는 구간)

"클립 N"은 발화를 시작한 시점의 순서로 고정해서 id에 연결합니다. 순서를 바꾼 뒤에도 뒤에 나오는 "클립 N"이 같은 클립을 가리키게 하기 위해서입니다. "그 자막", "방금 거" 같은 표현은 선택된 구간과 최근 대상 정보로 풀어냅니다.

## 3. 명령 목록

기존 편집 기능에 하나씩 연결합니다. 음성은 "1초 더", "조금 위로" 같은 상대 표현이 많아서, 절대값 명령과 함께 변화량 명령도 둡니다.

클립 관련
- extend_segment: 구간의 시작 또는 끝을 지정한 초만큼 늘림
- trim_segment: 구간을 지정한 초만큼 줄임
- set_range: 시작과 끝을 직접 지정
- swap_segments: 두 클립의 순서 교체
- move_segment: 클립을 지정한 위치로 이동
- delete_segment, set_speed, set_mute

자막 관련
- add_cue: 특정 클립 안에 자막 추가
- edit_cue_text: 문구 수정
- move_cue: 화면 위치 이동(상단, 중앙, 하단 또는 좌표)
- shift_cue: 시간을 앞뒤로 이동
- delete_cue, fit_cue_to_clip

스타일 관련
- set_style: 전체 또는 특정 자막의 폰트, 크기, 색, 위치 변경(상대값 허용)

기타
- add_extra_language, generate_subtitles, export, undo

예시로 "클립 1 길이 1초만 더 늘려줘. 클립 2랑 클립 3 위치 바꿔줘. 클립 2에 진짜 맛있겠다 자막 달아줘"는 다음 세 명령으로 변환됩니다.

- extend_segment: 클립 1의 끝을 1초 늘림
- swap_segments: 클립 2와 클립 3을 교체
- add_cue: 클립 2에 "진짜 맛있겠다" 추가

## 4. 프론트 명령 실행기

- 명령 목록을 순서대로 읽고, 종류에 따라 기존 편집 함수(예: 자막 추가 함수)를 호출합니다.
- 시작할 때 되돌리기 기록을 한 번만 열어서, 말 한 번이 ⌘Z 한 번으로 되돌아가게 합니다.
- 실행 전에 검증합니다. 없는 id, 영상 길이를 벗어나는 시간, 시작이 끝보다 뒤인 경우, 옆 클립과 겹치는 경우에는 해당 명령을 건너뛰고 이유를 알려줍니다.
- 영상 파일이 아니라 구간과 자막 같은 편집 데이터만 바꿉니다. 내보내기는 기존대로 GPU 서버의 ffmpeg가 구간과 자막을 처리합니다.

## 5. 모호함과 안전 처리

- 대상이 불분명하면 실행하지 않고 되묻습니다. 선택된 클립이 있으면 그것을 기본 대상으로 씁니다.
- 삭제나 대량 변경은 실행 전에 요약을 보여주고 확인을 받습니다.
- 음성에서는 따옴표가 없어서 자막 문구의 경계가 모호할 수 있습니다. 인식된 문장을 화면에 보여주고 수정할 수 있게 합니다.
- 짧은 음성에서 엉뚱한 문장이 나오는 것을 막기 위해 Whisper의 무음 구간 감지(VAD)를 유지하고, 소리가 없으면 결과를 버립니다.

## 6. 음성 처리 (Safari 포함)

- 브라우저 내장 음성 인식(Web Speech API)은 Safari에서 불안정해서 쓰지 않습니다. 대신 모든 브라우저에서 되는 MediaRecorder로 녹음하고, 인식은 서버의 Whisper로 통일합니다.
- Safari는 audio/mp4, Chrome은 audio/webm으로 녹음됩니다. 서버가 ffmpeg로 16kHz 모노로 변환하면 둘 다 처리됩니다.
- 마이크 권한 요청은 사용자의 버튼 클릭 안에서 해야 합니다. 누르고 말하기 방식이면 자연스럽게 충족됩니다.
- 마이크는 localhost에서는 HTTPS 없이 동작하지만, 다른 기기나 외부 주소에서는 HTTPS(ngrok 등)가 필요합니다.
- 응답 지연은 말이 끝난 뒤 1~2초로 예상합니다(아직 측정하지 않음).
- GPU 서버나 SSH 포워딩 연결이 끊기면 음성 인식이 실패하므로, 텍스트 입력을 대체 수단으로 둡니다.

## 7. 구현 순서

1. /agent/chat과 프론트 명령 실행기: 클립 길이·순서, 자막 추가·이동·스타일
2. GPU 서버 /stt, 백엔드 중계, 마이크 버튼(누르고 말하기)
3. 되묻기, 확인 화면, 결과 안내(필요하면 음성 안내), 대화 기록

## 8. 미확인 사항과 위험

- 클립 순서 바꾸기: 현재 화면에 순서 변경 기능이 있는지 아직 코드로 확인하지 않았습니다. 없으면 먼저 만들어야 합니다.
- 장면 다시 찾기: 한국어 문장을 영어 전용 CLIP에 그대로 넣는 기존 문제(GPU 서버에 OPENAI_API_KEY가 없음)를 고친 뒤에 연결해야 합니다.
- 한국어 말투 해석의 정확도는 프롬프트와 명령 설명을 반복해서 고쳐야 하며, 가장 많은 시간이 듭니다.
