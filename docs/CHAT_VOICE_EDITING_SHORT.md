# 채팅·음성 편집 (짧은 버전)

## 구현할 기능

채팅창에 편집하고 싶은 내용을 문장으로 입력하면, AI가 편집 화면을 대신 조작합니다. 마우스로 하던 클립 길이 조절, 순서 변경, 자막 추가·이동·스타일 변경을 채팅 한 줄로 지시할 수 있습니다. 같은 문장을 마이크로 말해서 입력하는 음성 모드도 지원해서, 책상에서는 채팅으로 정확하게, 누워서는 말로 대충 슥슥 편집할 수 있습니다.

기존의 정해진 명령(2배속, 음소거, 이동, 삭제)만 처리하던 방식에서 확장해, LangGraph 기반의 Stateful Editing Agent로 구현합니다. 이전 대화와 최근 편집 내용을 기억하기 때문에 "그 장면", "방금 수정한 부분" 같은 말도 이어서 처리합니다.

## 예시

- "클립 1 길이 1초만 더 늘려줘"
- "클립 2랑 클립 3 위치 바꿔줘"
- "클립 2에 '진짜 맛있겠다' 자막 달아줘"
- "자막 위로 올려줘", "자막 글씨 더 크게 해줘"
- "자막 밑에 영어 번역 추가해줘"
- "준비 장면 끝에서 10초 잘라줘" 하고 이어서 "그 장면 2배속으로 해줘"
- "방금 수정한 부분 취소해줘"
- 여러 개를 한 번에: "클립 1 1초 늘리고, 클립 2랑 3 바꾸고, 클립 2에 '진짜 맛있겠다' 자막 달아줘"

## 사용 모델과 위치

- 음성을 글자로: 학교 GPU 서버에서 Whisper(faster-whisper large-v3)를 씁니다. 자동 자막에 쓰는 모델을 그대로 재사용합니다. 브라우저에서는 MediaRecorder로 녹음해서 Safari에서도 동작하게 합니다.
- 문장을 편집 명령으로: 로컬 백엔드에서 LangGraph로 Editing Agent를 구성하고, LLM은 OpenAI API(gpt-4o-mini)를 호출합니다. 환경변수로 모델을 바꿀 수 있고, API 키는 로컬 백엔드에만 둡니다.

## Chrome·Safari 음성 처리

- 브라우저 내장 음성 인식(Web Speech API)은 Safari에서 불안정해서 쓰지 않습니다.
- 대신 모든 브라우저에서 되는 MediaRecorder로 녹음하고, 인식은 서버의 Whisper가 처리하도록 통일합니다.
- 녹음 형식이 다릅니다. Chrome은 audio/webm, Safari는 audio/mp4로 녹음됩니다. 서버가 ffmpeg로 같은 형식(16kHz 모노)으로 변환해서 Whisper에 넣으므로 두 브라우저 모두 같은 코드로 처리됩니다.
- Safari는 마이크 권한 요청을 사용자의 버튼 클릭 안에서 해야 합니다. 누르고 말하기 방식이면 자연스럽게 충족됩니다.
- 마이크는 localhost에서는 그대로 쓸 수 있지만, 다른 기기나 외부 주소에서는 HTTPS(ngrok 등)가 필요합니다.
- Safari 동작은 실제 기기에서 한 번 시험해야 확정됩니다.

## 데이터 가공

1. 프론트가 현재 편집 상태를 텍스트로 요약해서 보냅니다. 영상 길이, 클립 목록(id, 번호, 시작, 끝, 배속), 자막 목록, 선택된 대상이 들어갑니다. 영상 파일은 보내지 않습니다.
2. Agent는 세 단계로 요청을 처리합니다. 사용자 요청 → 요청 이해(무슨 편집인지 파악) → 맥락 해석(어느 장면인지 식별) → 상태 변경 명령 생성
3. 요청 이해에서는 "Trim 10 seconds from the end of the preparation scene"을 동작 TRIM, 길이 10초(action = TRIM, amount = 10s)로 파악합니다. 맥락 해석에서는 "preparation scene"을 scene_01로 식별합니다. 마지막으로 `scene_01.end -= 10s`라는 상태 변경 명령(JSON)을 만들고, 이 명령이 프론트 Timeline State에 반영되어 해당 구간이 00:10~00:40에서 00:10~00:30으로 바뀝니다. "클립 2랑 3 바꿔줘", "클립 2에 자막 추가" 같은 명령도 같은 방식으로 만들어집니다.
4. 그래프의 공유 상태(Shared State)에 이전 대화와 최근 편집 정보(Conversation + Previous Edit Context)를 저장합니다. 요청 이해와 맥락 해석 단계가 이 상태를 읽고 갱신합니다. 그래서 다음 요청(Follow-up User Request)인 "Make that scene 2x speed"처럼 대상을 다시 말하지 않아도 직전에 편집한 scene_01을 가리킬 수 있습니다.
5. "클립 N"은 말을 시작한 시점의 번호로 고정해서 id로 바꿔 둡니다. 순서를 바꾼 뒤에도 같은 클립을 가리키게 하기 위해서입니다.

## 적용 방식

- 요청 해석은 백엔드의 Agent가 하고, 변경 명령의 적용은 프론트가 합니다. 실제 편집 상태의 기준(source of truth)은 프론트의 Timeline State이고, Agent는 대화 맥락과 요청 해석, 변경 명령 생성만 맡습니다.
- Agent가 기억하는 것은 이전 대화와 직전 편집 내용(어떤 장면이나 자막을 어떻게 바꿨는지)입니다. 영상 자체는 기억하지 않습니다. 기억은 대화 세션 단위라서, 새로고침하거나 프로젝트를 다시 열면 이전 대화는 사라질 수 있습니다.
- 음성은 별도 편집 로직이 없습니다. Whisper가 목소리를 텍스트로 바꾸면 채팅 입력과 똑같이 처리합니다.
- 프론트의 명령 실행기가 JSON을 읽고, 마우스 편집과 같은 기존 편집 함수를 순서대로 호출합니다. 사용자가 직접 조작한 변경과 Agent가 만든 변경이 같은 경로로 반영됩니다. 바뀌는 것은 영상이 아니라 구간과 자막 같은 편집 데이터입니다.
- 실행 전에 없는 클립, 영상 길이 초과, 클립 겹침을 검사해서 문제가 있으면 건너뛰고 이유를 알립니다.
- 말 한 번이 되돌리기(⌘Z) 한 번 단위입니다.
- 애매한 지시는 되묻고, 삭제 같은 큰 변경은 실행 전에 확인을 받습니다.
- 영상은 마지막 "내보내기"에서 GPU 서버의 ffmpeg가 만듭니다.

## 진행 순서

1. 채팅 편집: LangGraph Agent의 세 단계와 명령 실행기 구현 (클립 길이·순서, 자막 추가·이동·스타일)
2. 대화 맥락 유지: Shared State에 이전 대화와 최근 편집 저장 ("그 장면", "방금 수정한 부분")
3. 음성 입력 연결 (마이크 버튼으로 같은 채팅창에 입력)
4. 되묻기·확인 화면 다듬기

## 현재 상태

구현 전 설계 단계입니다. 클립 순서 변경 기능이 현재 화면에 있는지는 아직 확인하지 못했고, 없으면 먼저 만들어야 합니다. 예시 중 장면을 다시 찾는 명령은 분석 정확도 개선 이후에 추가할 예정이라 위 목록에서 뺐습니다.
