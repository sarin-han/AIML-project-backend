# ClipCraft 작업 정리 (2026-10-29) — 보고서 작성용 자료

> 이 문서는 하루 동안의 개발 내용을 보고서로 옮기기 위한 사실 자료입니다. "확인함"과 "확인 못 함"을 구분해 적었으니, 보고서에서 성과를 쓸 때 이 구분을 지켜 주세요.

## 1. 프로젝트 개요

- **ClipCraft**: 텍스트로 설명한 장면을 영상에서 찾아 클립으로 잘라 주는 AI 영상 편집 도구(숏폼 제작 목적).
- **구성**
  - 프론트엔드: React + TypeScript + Vite(`clipcraft-web`)
  - 백엔드: FastAPI(로컬 실행, GPU 서버로 중계 + OpenAI 호출)
  - GPU 서버: FastAPI(연구실 서버의 Docker 컨테이너, RTX 4090 1장). CLIP 프레임 검색 → VideoLLaVA 검증 → 구간 확정, 영상 내보내기(ffmpeg)
- **기존 분석 흐름**: 영상 업로드 + 시나리오(장면 설명) 입력 → CLIP으로 후보 구간 검색 → VideoLLaVA로 검증 → 하이라이트 구간(시작/끝) 반환 → 편집 화면에서 구간 조절·배속·음소거 후 MP4 내보내기.
- **오늘의 목표**: 편집 결과물에 **자동 자막** 기능을 붙이고(Whisper), 자막 편집·스타일·내보내기까지 이어지는 흐름을 완성. 부수적으로 팀원이 만든 `ClipCraft-AI`(ReVisionLLM + 오디오)로 기존 분석 모델을 대체할 수 있는지 검토하고, 분석 정확도 문제를 점검.

## 2. 오늘 만든 기능

### 2.1 자동 자막 생성 (두 가지 방식)
| 방식 | 동작 | 사용 모델/API |
|---|---|---|
| 음성대로 만들기 | 영상 속 말소리를 인식해 구간별 자막 생성. 언어는 자동 감지/한국어/영어 선택 | GPU 서버의 `faster-whisper large-v3`(float16, GPU). 무음 구간은 VAD로 제외 |
| 시나리오대로 만들기 | 말소리가 없는 영상용. 분석에 입력한 시나리오 문장을 짧은 자막 문구로 변환. 톤 선택(설명형/감성형/유머형) | OpenAI `gpt-4o-mini` |
- 영어 등 한국어가 아닌 말소리는 인식 후 **한국어로 번역**(OpenAI). 원문은 따로 보관해 **두 줄 동시 표시**(원문 위, 번역 아래) 가능.
- 음성 자막과 시나리오 자막을 **따로 저장**하고 버튼으로 전환. 편집·내보내기는 선택한 쪽 기준.
- 음성이 없거나 오디오 트랙이 없을 때 안내 문구를 보여주고 시나리오 방식을 권유.
- **다른 언어 자막 추가(OpenAI API로 변환)**: 한국어 자막 아래 줄에 영어·일본어·중국어(간체)·스페인어·프랑스어·독일어·베트남어·태국어·한국어 중 한 언어를 번역해 추가. 언어를 바꿔 다시 변환 가능, 줄마다 수정 가능, 미리보기·SRT·영상 내보내기에 반영. 아래 줄은 위 줄보다 15% 작게 그림. 번역은 로컬 백엔드가 OpenAI(`gpt-4o-mini`)로 처리.
- 비전(프레임 기반) 자막 생성 API도 구현했으나 요청에 따라 화면에서는 뺌(백엔드 API는 남아 있음).

### 2.2 자막 편집
- 문장 수정·삭제, **자막 추가**(버튼 또는 자막 줄 빈 곳 더블클릭).
- **파형 아래 자막 줄**: 막대 끝을 끌어 길이 조절, 몸통을 끌어 이동. 끌 때 **클립(장면) 경계·다른 자막·재생 위치·영상 처음/끝에 자석처럼 붙음**(보라색 맞춤선, Alt로 해제).
- 선택한 자막의 시간을 클릭해 숫자로 수정. 시나리오 자막에는 "클립 길이에 맞추기".
- 영상 화면 위에서 자막을 **끌어 위치 이동**, 모서리 핸들로 **크기 조절**, 가운데·1/4 지점·여백선에 **격자 맞춤**.
- 목록의 자막을 **파형(시간) 또는 영상 화면(위치)으로 끌어다 놓기**.
- **장면과의 연결**: 내보내기에는 선택한 장면(하이라이트 구간) 안에 걸친 자막만 사용. 목록은 선택한 클립의 자막만 보여주고 "전체 자막 보기"로 전환. 장면 밖 자막은 흐리게 표시하고 일괄 삭제 가능.

### 2.3 자막 스타일
- 폰트 11종(서버에 설치한 무료 오픈 라이선스 한글 폰트), 크기(숫자 입력), 위치(상단/중앙/하단), 색(흰색~검정 회색 단계 + 직접 고르기), 배경 박스.
- **전체 기본값**과 **자막별 개별 스타일**을 따로 지정 가능.

### 2.4 자막을 영상에 입혀 내보내기
- "MP4로 내보내기"에 **자막 포함** 옵션. 선택한 구간의 순서·배속을 반영해 자막 시간을 다시 계산하고, GPU 서버가 ffmpeg(libass)로 영상에 자막을 입힘. SRT 파일만 받기도 가능.
- **SRT 대신 ASS 형식**을 만들어 사용: 자막마다 폰트·크기·색·위치가 다를 수 있어서 SRT로는 표현이 불가능했기 때문.

### 2.5 편집 화면 전반
- **되돌리기/다시 실행**(⌘/Ctrl+Z, ⌘/Ctrl+Shift+Z): 구간 편집, 배속·음소거, 삭제, 자막, 자막 기본 스타일 대상. 끌기처럼 이어진 변경은 한 번으로 묶고 추가·삭제 같은 단발 작업은 각각 기록.
- **파형 확대/축소**(버튼, ⌘/Ctrl+스크롤, 좌우 스크롤 이동, 선택 자막 확대, 재생 위치 자동 추적). 최대 확대는 화면에 약 3초.
- AI 어시스턴트를 헤더 버튼으로 여닫는 오른쪽 열로 변경, 전체 여백·열 비율 조정, 자막 패널 버튼 정리.

## 3. 시스템 변경 요약

| 위치 | 변경 |
|---|---|
| GPU 서버 | `POST /transcribe/jobs`, `GET /transcribe/jobs/{id}` 추가(Whisper, job 방식). `/export`에 `subtitle_cues`(아래 줄 `bottom` 포함)·`subtitle_style`(`extra_lang`) 추가(ASS 생성, 추가 언어는 언어별 폰트 지정) |
| 백엔드 | `/transcribe/*` 중계, `POST /translate`(대상 언어 9종 선택), `POST /suggest-subtitles` 추가. OpenAI 키는 로컬 백엔드에서만 사용 |
| 프론트엔드 | 자막 패널, 자막 줄(파형 아래), 화면 위 자막 오버레이, 되돌리기, 파형 확대 등 |
| 문서 | `docs/PROGRESS.md`(진행 기록), 이 문서 |
| 테스트 | `e2e/editor-undo.spec.ts` 추가, 기존 `editor.spec.ts`의 채팅 입력 전에 어시스턴트를 여는 단계 추가 |

주요 설계 결정과 이유
- 작업을 **job 방식**(시작 → 상태 조회)으로 구현: 기존 분석 API와 같은 패턴, 긴 작업 대응.
- **OpenAI 키를 GPU 서버로 보내지 않음**: 여러 학생이 쓰는 공용 서버라서 번역·자막 문구 생성은 로컬 백엔드에서 처리.
- Whisper를 **로컬 모델**로 선택: GPU가 있어 비용이 없고 외부 전송이 없음.
- 자막 입히기는 **ASS + 영상 실제 해상도 좌표계**로 생성해 화면 미리보기와 결과물의 크기·위치가 같도록 함.

## 4. 측정·검증 결과

### 4.1 확인함 (직접 실행해 결과를 본 것)
- **Whisper**: 한국어 TTS 7분 45초 음성 → 인식 약 14초(영상 길이의 약 3%), 자막 80개. 한국어·영어 음성 모두 정확히 인식. 한국어로 고정한 설정에 영어 음성을 넣으면 한국어로 지어내서 엉뚱한 글자가 나오는 것도 확인(그래서 언어 자동 감지를 기본으로 함).
- **번역·다국어 변환**: 영어 → 한국어, 한국어 → 영어·일본어·태국어 번역 API 호출 결과 확인. 지원하지 않는 언어 코드는 400으로 거부.
- **다국어 자막 입히기**: 한글 자막 아래에 일본어·중국어·태국어·베트남어(성조 표기 포함)·스페인어(¿·악센트 포함)가 깨지지 않고 입혀짐을 내보낸 영상 프레임으로 확인.
- **다국어 화면 흐름(Playwright, 실제 백엔드·OpenAI 사용)**: 자막 추가 → 일본어 변환 → 입력칸에 번역 채워짐 → 내보내기 요청에 아래 줄 자막과 `extra_lang: ja`가 실리고 자막 시간이 선택한 장면 기준으로 재계산됨 → 수정·지우기 동작.
- **자막 입히기**: 폰트 3종·크기·위치·색·박스 조합, 두 언어 동시 표시, 자막별 개별 스타일(한 영상에 기본/개별 스타일 혼합), 자막별 위치 지정이 내보낸 영상 프레임에 실제로 반영됨을 이미지로 확인. 잘못된 폰트 id·톤은 400으로 거부됨.
- **시나리오 자막 문구**: 시나리오 기준(텍스트만)·영상 기준(프레임만) 호출 모두 결과 확인.
- **브라우저 자동 테스트(Playwright, Chromium)**: 되돌리기/다시 실행(버튼, Ctrl+Z, ⌘+Z, Ctrl+Shift+Z, 다단계 연속 편집), 자막 추가(버튼·더블클릭), 자막 끝을 클립 경계(50초) 근처로 끌면 정확히 `0:50.0`에 붙는 자석 맞춤, 클립 길이에 맞추기, 장면 밖 자막 숨김/삭제/되돌리기, 선택한 클립 자막 보기와 "전체 자막 보기", 어시스턴트 토글 후 채팅 명령 통과.
- **성능(크롬 기준)**: 자막 80개 + CPU 6배 감속에서 파형 클릭 화면 반응 25~34ms, 4분 30MB 영상에서 클릭 후 영상 이동 40~110ms(이동 이벤트 1회, 되돌림 없음). 타입 검사(tsc) 통과.

### 4.2 확인 못 함 (코드와 타입 검사만 통과, 화면은 직접 눌러 보지 못함)
- 영상 화면 위 자막 끌기·모서리 크기 조절·격자 맞춤, 목록에서 파형/화면으로 끌어다 놓기, 파형 확대/축소, 자막 스타일 패널의 개별/전체 전환, 음성↔시나리오 전환 버튼, 레이아웃·여백 조정, 버튼 모양 변경(사용자가 직접 확인 중).
- 다른 언어 자막의 번역 품질(고유명사·말투), 한 번에 한 언어만 추가 가능한 제한의 사용성.
- 실제 사람 목소리·배경음악이 섞인 영상의 Whisper 정확도(측정은 TTS 음성 기준). 음악 영상은 가사 인식이 부정확할 수 있다고 안내.
- 사용자가 겪은 "파형 클릭이 느림"은 크롬에서 재현하지 못했음(사용 브라우저 확인 필요).
- 기존 `editor.spec.ts`는 마지막 단계(`hidden-segment-indicator`)에서 실패하는데, 이 요소는 이전 개발자 커밋에서 이미 코드에서 사라진 것이라 **이번 변경과 무관한 기존 실패**.

## 5. 분석(구간 선택) 정확도 점검

- **증상**: 서로 다른 시나리오가 모두 `0초~몇 초` 구간으로 겹쳐 나옴.
- **원인**: GPU 서버 프로세스에 `OPENAI_API_KEY`가 없어서 시나리오를 영어로 바꾸는 단계(`OpenAIQueryExpander`)가 동작하지 않고, 한국어 문장이 영어 전용 CLIP(ViT-L/14)에 그대로 들어감. 서버 로그에 `[expand] OPENAI_API_KEY is not set. Using the original query.` 확인.
- **검증(같은 영상·같은 모델, 3:56 드라마 영상)**

| 시나리오 | 한국어 그대로 | 영어로 변환 |
|---|---|---|
| 남자가 여자에게 물을 건넴 | 0~3초, 75~87초, 229~236초 (최고점 0.175) | 97~103초, 111~117초, 125~131초 (최고점 0.233) |
| 여자가 물을 마심 | 0~3초, 75~87초, 229~236초 (0.174) | 11~17초, 185~191초, 231~236초 (0.184) |
| 소파에 앉은 남자 여자 | 0~3초, 75~81초, 229~236초 (0.176) | 99~105초, 125~131초, 183~189초 (0.248) |

  → 서로 다른 한국어 쿼리 3개가 거의 같은 구간과 같은 최고점 위치(192초)를 냄. 영어로 바꾸면 시나리오마다 다른 구간과 더 높은 점수.
- **함께 있는 약점**: 점수가 낮아도 항상 상위 3개 구간을 반환(최소 점수 기준 없음), 프레임 샘플링 0.5fps, VideoLLaVA 검증에도 한국어 시나리오 전달.
- **해결 방향(미적용)**: 로컬 백엔드에서 시나리오를 영어로 변환해 GPU 서버로 넘기고(키를 공용 서버에 두지 않기 위해), CLIP과 VideoLLaVA 양쪽에 적용, 낮은 점수 구간 걸러내기. 사용자 승인 대기 중.

## 6. ClipCraft-AI(ReVisionLLM + 오디오) 연동 검토

팀원이 만든 `ClipCraft-AI`와 팀원 보고서 2건(PDF)을 읽고 기존 CLIP + VideoLLaVA 대체 가능성을 검토.

- **모델**: 공개 ReVisionLLM(CVPR 2025, 영상+문장 → 시작/끝 구간 직접 예측)에 CLAP 오디오 분기를 추가. 오디오 특징을 어댑터 앞 CLIP 프레임 특징에 더하는 방식, 2단계 학습(오디오 분기만 → 분기+어댑터+LoRA).
- **학습/평가 데이터**: Charades-STA(약 5,300 영상·12,400 질문, 대부분 약 30초 실내 영상) + VidChapters-7M 긴 영상 125개(긴 영상 능력 유지용 보조). 평가는 Charades-STA 테스트 1,334 영상·3,720 질문.
- **팀원 보고서의 성능**(mIoU / R1@0.5): R0(미세조정 전) 16.90 / 14.27, R1(영상만) 52.50 / 61.34, **R2(영상+오디오) 53.26 / 62.63**, R4(R2에서 추론 때 오디오 제거) 52.17 / 61.13. R2−R4 차이는 통계적으로 유의. 오디오 단서가 있는 질문(웃음·문소리 등)에서 효과가 집중되고 시각 중심 질문 성능은 유지.
- **멀티쿼리 + 캐시**(팀원 보고서): 300 영상·822 질문에서 질문당 처리시간 2.54초 → 1.22초(약 52% 감소), 20개 질문 45.3초 → 5.9초(약 7.7배). 정확도는 샘플링 노이즈 범위에서 유지.
- **우리 서비스에 적용할 때의 막힌 점**
  1. 저장소에 가중치가 없음(R2 체크포인트, 공개 ReVisionLLM, Vicuna-7B, CLIP, CLAP) → 팀원에게 받아야 함
  2. 패키지 버전 충돌(`torch 2.4.1`, `transformers 4.41.2` 등이 GPU 서버 환경과 다름) → 별도 환경/프로세스 필요
  3. 의미 캐시에 PostgreSQL + pgvector 필요
  4. **긴 영상·요리 영상 성능이 검증되지 않음**(학습·평가가 짧은 실내 영상 위주), 영어 쿼리 전제(한국어는 번역 필요)
  5. Charades·VidChapters·공개 사전학습 가중치 모두 **비상업 연구용 라이선스**
- **결론**: 기술적으로 대체 가능하나, 가중치 확보와 실제 서비스 영상(짧은 영상·긴 영상)에서의 비교 평가가 먼저 필요. 그 결과로 R2/R0/기존 방식 중 선택(짧은 영상 R2, 긴 영상 R0 또는 기존 방식으로 나눠 쓰는 것도 가능).

## 7. 개발 중 발견·해결한 문제 (보고서 소재)

## 8. 보안·운영 메모

- 개발 중 공유된 **서버 접속 비밀번호와 OpenAI 키가 대화에 평문으로 노출**됨 → 작업 후 비밀번호 변경, 키 교체 권장.
- **`.env.example`(git이 추적하는 파일)에 실제 OpenAI 키가 들어 있음.** 커밋에서 제외해 두었으나 푸시 전에 비워야 함.
- GPU 컨테이너의 8001 포트는 외부에 열려 있지 않아 SSH 포트 포워딩으로 연결. 외부 공개 터널(Cloudflare)은 서버를 인터넷에 노출하므로 사용하지 않음.
- 컨테이너가 재시작되면 GPU 서버를 다시 띄우고 포트 포워딩을 다시 열어야 함.

## 10. 보고서 결정 기록 문안(최종본)

보고서에 넣기로 정한 Decision 3·4 문안입니다. "추가 검증이 필요하다"는 문구는 요청에 따라 뺐습니다. Decision 4의 "주요 편집 동작을 검증"은 4.1의 Playwright 목록 범위(되돌리기, 자막 추가, 경계 맞춤, 장면 밖 자막 처리, 다국어 변환)만 사실이며, 영상 화면 위 끌기·크기 조절, 파형 확대·축소 등은 4.2에 있듯이 자동 검증하지 못했습니다.

**Decision 3. Whisper 기반 자동 자막 생성 기능 구현**

GPU 서버에서 `faster-whisper large-v3`를 직접 실행해 영상 속 음성을 인식하고 자막을 생성하는 기능을 구현하였다. 언어는 자동 감지를 기본으로 해서 영어 음성도 인식하고 한국어로 번역하며, 말소리가 없는 영상은 시나리오 문장으로 자막을 만들 수 있게 했다. 자막 수정, 스타일(폰트·크기·위치·색) 설정, 타임라인 조절을 지원하고, 자막마다 스타일이 달라 ASS 형식으로 영상에 입혀 내보낸다. 7분 45초 음성이 약 14초에 인식되는 것을 확인했다.

**Decision 4. OpenAI API 기반 다국어 자막 및 편집 기능·UI 개선**

OpenAI API(`gpt-4o-mini`)를 활용해 자막을 영어·일본어·중국어 등 여러 언어로 변환하고, 한국어 자막 아래에 다른 언어 자막을 한 줄 더 추가할 수 있도록 하였다. 파형 아래 자막 줄에서 끌어서 길이를 조절하고 클립 경계에 자동으로 맞춰지게 했으며, 영상 화면 위 자막 이동·크기 조절, 실행 취소·다시 실행, 파형 확대·축소를 구현하였다. 자동화 테스트(Playwright)로 실행 취소, 자막 추가, 경계 맞춤 등 주요 편집 동작을 검증하였다.
